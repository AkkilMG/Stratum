Studio / NAS hub

Share a space across a team using a bare Git repo on a NAS or Git server.

A studio hub lets several people share one space through a bare Git repository — on your NAS, a local server, or any Git host. Stratum handles the plumbing so the team doesn't have to.

What a studio hub is

A hub is just a bare Git repository — no working copy, only history. Each person keeps their own local space and points it at the hub. Stratum pulls other people's versions and pushes yours automatically.

shell
# A hub is created like any bare repo:
git init --bare //NAS/studio/stratum/art.git

Create a hub

  1. Open the space you want to share.
  2. Choose Share this space (or Settings → This space → Change remote).
  3. Select Create shared space and enter the remote location.
  4. Optionally enable Git LFS for large files, then confirm.

Join a hub

  1. From the home screen choose Join a studio space.
  2. Enter the same remote location a teammate used.
  3. Pick a local folder and let Stratum clone it.

Tip

Everyone should point at the same bare repo URL. Pasting the exact path your teammate used is the surest way to avoid a mismatch.

NAS specifics

Network shares can be slow or briefly unmapped. Stratum accounts for this:

ConcernHow Stratum handles it
Unreachable sharesSync reports Waiting and retries; local work continues.
Slow metadata accessUses polling-friendly strategies instead of relying on native file events.
Index locationThe SQLite index and thumbnails live locally, never on the share.
PathsWorks with both mapped drives and UNC paths.

Large files & LFS

Textures, PSDs and videos can be large. Enable Git LFS when creating the hub so big binaries are stored efficiently and clones stay fast. If LFS isn't available, Stratum still versions the files normally — commits are simply heavier.

Note

LFS needs to be enabled in the client where the hub was created. Joiners inherit the setting through the repository's .gitattributes.

Team workflow

  • Sync happens automatically every couple of minutes — no manual ritual required.
  • Use Sync now before closing for the day to be sure everything is pushed.
  • Tags and version history are shared, so everyone sees the same labels and timeline.
  • Conflicts are preserved side-by-side rather than dropped.
